# Backlog

Single source of truth for concrete, independently-implementable work. Read `PROJECT_PLAN.md` first for the reasoning behind phase order and for the Assumptions this backlog relies on.

**How to use this file**
- Each task has a stable ID (`T-0XX`), never reused or renumbered even if a task is dropped (mark it `Won't Do` instead of deleting).
- Status values: `Not Started` | `In Progress` | `Blocked` | `Done`. Update the `Status:` line in place when work happens — that's the only thing that needs to stay grep-friendly (`grep "Status: Not Started"`).
- `Depends on:` lists task IDs that must be `Done` first. `None` if it has no dependency.
- `Source:` traces the task back to `requirements-raw.md` (row number) or to an informal note / assumption in `PROJECT_PLAN.md`.
- `Acceptance Criteria:` is written so the Test role can verify it directly against running software — concrete, observable outcomes, not vague goals.
- When you finish a task, also add one line to `PROGRESS_LOG.md`.
- New work discovered mid-build gets a new task ID appended at the end of its phase's section (or a new phase if truly new scope) — never silently done off-backlog.

**What already works well for many classes** (confirmed for real by the Leader against the source, not just the persona's word): the class-card home shows an attention badge per class with no need to open any of them; `AssignTestToClassesDialog` (built in Phase 15) lets a teacher tick several classes at once in one action and correctly disables/greys out classes that already have that test (`assignedIds.has(cls.id)` in `client/src/components/AssignTestToClassesDialog.tsx`); the class-header "CHUYỂN SANG LỚP KHÁC" switcher lets a teacher change class without leaving the current tab.

**Findings, ranked, not yet fixed — customer to prioritize**:
- **Nặng — No "Nhân bản" (duplicate) for a test or flashcard set.** Confirmed by the Leader: no such feature exists anywhere in the code (`client/src/pages/TeacherTestsPage.tsx`/`TeacherTestEditorPage.tsx`/`TeacherFlashcardsPage.tsx`, no server route). A teacher reusing an existing test as the base for a similar one (a very common multi-class case) must retype or hand copy-paste every question. Suggested: a "Nhân bản bài kiểm tra" button on the Library test list and inside the editor (and the same for flashcard sets), creating an unpublished copy with fresh variants, assigned to nobody yet.

A teacher with the same test's essays ungraded across several classes must finish one class, then manually switch classes and restart the grading queue there — once per class. Suggested (needs a decision, not built): either a class-crossing grading queue for "this test, every class", or at least a visible "Bài viết còn thiếu ở các lớp khác" pointer at the "all done" screen.
