# Integrations requiring customer-supplied credentials

This file lists every part of the product that is **fully built against a mock/stub** and
only needs real third-party credentials/accounts swapped in when the customer provides them.
Nothing here is allowed to block progress — per `TECH_STACK.md`'s integration rule, Dev builds
the full business logic + UI + data flow against a mock/stub, logs it here, and moves on.

| Integration | Code location | What customer must supply | Current mock/stub | How to activate |

| AI Essay/Writing-grading provider (`EssayGradingProvider`) | **Built (2026-09).** Interface: `server/src/grading/essayGradingProvider.ts` (`EssayGradingProvider.grade(input): Promise<{ score, feedback, criteria }>`). Mock implementation: `server/src/grading/mockEssayGradingProvider.ts` (`MockEssayGradingProvider`). Real (ready, unregistered-by-default) implementation: `server/src/grading/anthropicEssayGradingProvider.ts` (`AnthropicEssayGradingProvider`) — calls `https://api.anthropic.com/v1/messages` directly via `fetch`, graded against `IELTS_WRITING_BAND_DESCRIPTORS`, a condensed but genuine IELTS Writing band-descriptor system prompt (Task Achievement for Task 1 / Task Response for Task 2, Coherence & Cohesion, Lexical Resource, Grammatical Range & Accuracy, bands 4–9). Factory/swap point: `server/src/grading/index.ts`'s `getEssayGradingProvider()`, called once per essay question from `POST /api/attempts/:attemptId/submit` in `server/src/routes/attempts.routes.ts` (essays have no per-question submit moment the way Speaking does — every essay in the attempt is graded in parallel right before the transaction that finalizes the score). Teacher grading UI (pre-filled from the AI's suggestion, overridable) is `TeacherAttemptDetailPage.tsx`; student view is `AttemptResultPage.tsx`. **Activated (2026-10), via a SECOND, higher-priority implementation**: `server/src/grading/openAiCompatibleEssayGradingProvider.ts` (`OpenAiCompatibleEssayGradingProvider`) calls any OpenAI Chat-Completions-compatible endpoint (base URL + API key + model — the same 3 fields Cline's "OpenAI Compatible" provider asks for), configured entirely from the admin UI (`AdminSettingsPage.tsx`'s "AI essay/writing grading" section) rather than env vars — admin-only `GET`/`PATCH /api/admin/settings/ai-grading` in `adminSettings.routes.ts`, stored on `Settings.essayGrading*` (`schema.prisma`), key encrypted at rest via `server/src/lib/secretCrypto.ts` (AES-256-GCM, keyed from `JWT_SECRET`). `getEssayGradingProvider()` in `./index.ts` checks this DB config FIRST (fresh on every call, no restart needed to pick up an admin edit) and only falls back to the env-driven path below when it's off or incomplete. The grading PROMPT itself (`DEFAULT_ESSAY_GRADING_SYSTEM_PROMPT`, pulled out to `server/src/grading/essayGradingPrompt.ts` so both real providers share it) is also admin-editable from that same UI section, with a "reset to built-in default" action. | A real Anthropic API key (`ANTHROPIC_API_KEY`) for the (now secondary, env-driven) Anthropic path — OR, for the admin-UI path above, an API base URL + key + model for any OpenAI-compatible endpoint, entered directly in Settings. | `MockEssayGradingProvider` — a documented heuristic blending word-count-vs-target, paragraph/linking-word coherence, vocabulary-diversity lexical resource, and average-sentence-length grammar proxies into a 0–9-band or free-form score (see the class's doc comment). It's what's used whenever the admin-UI config above is off/incomplete AND `ESSAY_GRADING_PROVIDER` is unset/`mock` (both default), so the whole essay-AI-grading flow (submit → auto-grade → teacher pre-fill/override → student result) still works end-to-end with zero configuration. | **Admin-UI path (now the primary one): no `.env` edit needed at all** — open `/admin/settings`, fill in the API base URL, model, and API key under "AI essay/writing grading", optionally edit the grading prompt, and toggle it on (the server rejects enabling until base URL + model + key are all present). Takes effect on the very next essay submission, no restart. **Env-driven Anthropic path (secondary, still available)**: 1. (Already done) `AnthropicEssayGradingProvider` exists and is already registered in the `switch` in `getStaticEssayGradingProvider()` (inside `./index.ts`). 2. Add `ANTHROPIC_API_KEY` to `server/.env` (documented in `.env.example`). 3. Set `ESSAY_GRADING_PROVIDER=anthropic` in `server/.env`. Either path: submission, scoring (`attemptScore.ts`), the "awaiting grading" queues (`classAttention.ts`), and the teacher/student UI are all provider-agnostic; they only ever see `{ score, feedback, criteria }`. |
